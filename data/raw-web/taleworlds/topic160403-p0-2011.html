Persistent World 4 alpha - download and general discussion
« on: March 01, 2011, 02:38:43 PM »
Background information:

This is an incomplete, buggy, and experimental release of a revised game mode in the spirit of early PW and PW WAR: it was started soon after PW version 2 was released, over six months ago, and was intended to be released as PW version 4. The native module system data was almost entirely removed - leaving only the definitions for a few things like animations, particles, meshes, sounds, and the game credits - creating a new multiplayer game mode from scratch: designed that multiple factions battle for castles and resources over a longer time period than native modes, of a few hours at least.

Version 3 of PW has tended towards being played less battle oriented, with more prearranged roleplaying, but this version was designed before that became popular, so might not be a very good fit for the current servers, at least for a while. It doesn't really share any data or more than a few bits of some scripts with the previous versions, and only the native parts of existing scenes will load; so most PW RP servers might want to stick with version 3.x, for a while at least - this release is primarily a test. If server admins want to use this version instead of 3.x, be warned: features of 3.x are missing that "peaceful RP" players probably want, like lots of free respawn gold, new heraldry created by players, free ability to create as many "factions" as you want, local chat as the default, the balance of stats / prices / economy in the 3.x versions, and probably more.

Main features:
  • Up to 6 factions (which native MP calls teams): commoners (which everyone starts as), outlaws (which repeatedly team killing restricts you to), and 4 castle owning factions.
  • Troop types are not selectable before spawn: you need to pay money and train for a certain amount of time with one of the factions. Some troop types have special abilities, like engineers for building, doctors for healing, brigands best at lock picking, and serfs for the dirty work.
  • Troop type, faction, gold, and more are saved every few seconds and restored (only a percentage for the gold) when rejoining the server, until the mission ends or the server crashes. This is not the same as cRPG: all data is wiped at the start of the next mission (map / round / game / whatever).
  • Enhanced item buying scene props, which combine buying, selling, stockpiling, and crafting; showing the item stats. Most weapon stockpiles require crafting by engineers from resources before they can be bought from; armour buying props currently don't require crafting, but some probably will in future.
  • Destructible trees and iron mines to harvest resources; trees regrow after being cut down.
  • Repairable and buildable scene props, like doors, ladders, walls, and bridges. Doors can be locked, only able to be opened by players in the correct faction.
  • Drawbridges and improved portcullises.
  • Doors which teleport players to the location of the other linked door, so the native interiors can be used, underneath the terrain.
  • Ships that can be sailed, ideally with two players; they can also be damaged, repaired, and sunk.
  • Castles that can be captured: which changes the door locks, flags, and more. The method of capturing a castle is still very basic, and will probably be expanded.
  • Castle faction lords, which are players voted in by faction poll; they can set the faction name, banner, withdraw money from the faction chest, and access a unique troop type. Their role will probably be expanded in future versions.
  • Money bag items, to transfer gold between players. Loot bags are dropped when a player dies, taking a small amount of their gold and part of the value of their equipped armour; all weapons should be dropped. The display error with gold values over 131071 has been worked around.
  • Player invulnerability for 10 seconds after spawning (you cannot attack or be attacked); the time might be extended or reduced.
  • Doctors can heal badly injured players up to a certain point, while resting on beds is for fully healing lightly injured players.
  • Outlaw ratings for players, which are currently only increased by team killing, and which decrease slowly over time. If a player's outlaw rating is too high they are set to the outlaws faction, and when they die they can only train as the weaker outlaw troops until their rating drops low enough.
  • Some simple administrator tools.
  • An optional feature to use an external web server to restrict player names and clan tag prefixes to specific player serial numbers. One name server could be used for multiple Warband PW servers.
  • More ways for scene makers to adjust how the game mode works, by setting edit mode scene prop values; things like associated castle, gold value multiplier, linked scene prop, initial state, initial hit points, scene time of day, and which factions are available.
Known issues, probably not fixable:
  • Death messages should appear green when you kill someone, and red for all others, like deathmatch; this is due to a hard coded restriction on the number of teams.
  • Items dropped on the ground by players will disappear after about 3 minutes; this seems to be hard coded.
  • If the faction banner is changed more than once in about a minute, the castle flag will be wrong for another minute; this is due to how the engine handles tableaus for items not equipped by an agent. Castle flags might not show up at all for a minute or so after joining the game.
  • There is no way to remove any armour, and all troops spawn with head armour; this is due to a bug (or missing feature) in the game engine. When equipping items that show hair, for example the wedding veil, the player will have a bald head until they respawn with the item equipped (or for other players, reconnect to the server). I have some ideas on how it might be possible to work around this problem, eventually, but the best solution would be taleworlds fixing it.
  • Projectile items disappear when fired or thrown under the terrain level, like when inside most interiors.
  • If money bag items are wielded when a player dies, an extra empty bag will be dropped (by the game engine).
Known issues, hopefully will be fixed:
  • The supplied scene is pretty incomplete in areas, and is probably very unbalanced; it was mainly created as a testing scene, and so I could get an idea of what features would be useful for scene makers. There will probably be a lot of scenes made by other people, anyway.
  • Iron mines disappear permanently after they are exhausted, as opposed to the regrowing trees; a system to replenish them might be added, but for a start I'd like to see how the end game works out with no new iron.
  • The code for saving player troop, faction, money, and other data might not be absolutely reliable - sometimes the previous data is not used when reconnecting - though this might be something that only happens with one player connected. Any changes in about the last 5 seconds might not be saved, by design; though when you die the data is saved immediately, to restrict cheating.
  • Bridge, ladder, and wall construction scene props don't show the correct hit points value of the linked scene prop.
  • Horses sometimes seem to drown when not underwater; I haven't figured out why yet.
  • The animation of the ships might be very jerky and glitchy looking, probably depending on your FPS; I have hardly any idea how they will work on remote servers.
  • The ship ramp doesn't match the ground level very well.
  • In DirectX7 mode, the outer sea mesh doesn't stay at sea level, sloping upwards and looking ugly - it works fine with DirectX9.
  • When a faction banner is changed, sometimes not all heraldic armor worn by other players will be redrawn; I don't know why.
Incomplete and buggy features, not meant to be used yet:
  • Carts: these have quite a few potential problems, besides looking glitchy at the moment: they can be swung into players to fling them around, and swung through the terrain or scene props. Doing collision detection on all other props in the scene might be hard on the server - boats are simpler in that not many scene props or players are in or near the water - but it might be added, eventually.
  • Item storage scene props: the code to transfer items is (theoretically) mostly done, but the client side presentations still need some work.
  • Local chat window: this was just a quick test to see what could be done (which is not much, without using things like the WSE on clients).
Obvious features that I've avoided until after a release, to avoid taking too much time:
  • Animals (human bots probably won't be added).
  • Food, hunger, extra resource types and associated processing.
  • Emotes - sounds, animations.
  • Siege equipment.
  • Admin chat and more tools.
  • Changing weather - depending on what is possible.

Download information:

This mod has a definite requirement for Warband version 1.134 or greater, for both the server and the player clients; older versions will have many problems, if they even run it at all. To play the game you must connect to a dedicated server: client hosted servers are not supported at all, since they would require a lot of extra code added; the "Host a Game" feature has been entirely replaced by a scene editing mode.

-- 4 alpha3:
Allow players to select the next spawn point after they die.
Fix  "sticky" player list overlay (pressing tab).
Fix so ships still work after a map change.
Ship types have different top speeds now: the small longboats are fastest, bigger ones are slightly slower.
There are more gradual steps of ship forwards speed, and overall ships have been slowed down.
Reduce damage to ships when they crash.
Increase ship hit points.
Possibly fixed phantom collisions above sunken ships.
You can't use up arrow to climb the side of a sunken ship any more.
Reduce gold loss on rejoin to 10% - 20%.
Cut training prices in half, except for outlaws, which are increased slightly.
Double resource prices, roughly.
Added more bushes and wood exporting stations.
Increase the effect of labouring skill, so peasants should be able to work faster.
Reduce the amount of damage to cut branches from a tree (this might be reverted).
Increase wooden bridge hit points.
Give serfs faction colored hats.
Reduce the price of the surgeon's scalpel.
If players are outlawed as a peasant or serf, they won't be "upgraded" to a ruffian on next spawn anymore.
Outlaw rating is shown on your clients more, and once you are outlawed it must drop to 0 before you can switch to commoners again.

-- 4 alpha2:
Added mercenary troops which can only be trained as when that faction owns no castles, to allow the faction to recapture a castle.
Worked around the stick selling exploit by making it a melee weapon only.
Added some default tools for peasants and serfs; they are lower quality.
Repairing ships is fixed.
Added an admin command to reset all sunk ships to their initial position.
Added a faction lord command to kick a player from your faction; this costs money, so it hopefully isn't overused.
Changed some conflicting meshes that made the small trees (which anyone can cut sticks from) very hard to hit.
Added a server console option to make killed commoners (peasants) drop no loot: "set_force_default_armor 1".
Added a server console option to disable admin gold: "set_disallow_ranged_weapons 1".
Some other miscellaneous fixes.
