## Decisions implemented

- **Profile:** River chose the display case. The familiar avatar stays beside the member name. The exact supplied Volunteer shoulder patch sits upright, with no CSS rotation. Rank and medals share a subtle cloth surface; combat results remain a compact separate panel.
- **Large medal collections:** eight medals initially, two balanced rows on desktop; Show all expands the complete visible collection with no hard cap. Phone expansion gives the medals the full case width. Twenty labelled reference patches test the layout; they are not fabricated member awards.
- **Hidden awards:** owner/staff Manage display has separate Hide/Show controls. Hidden awards stay on the record but do not enter either the compact or expanded display. Hiding is presentation, not deletion, revocation or a new privacy boundary. The existing personnel read policies are unchanged.
- **Weekly brief:** ornamental border is outside a true 16:9 media area. Its bottom edge no longer covers playback controls, and it cannot overlap the right rail. Caption and navigation sit below the media, outside the frame. Approved images and direct videos participate alongside YouTube; unsupported sources have an honest link fallback. Hidden-tab rotation pauses.
- **Landing/header:** full-photo option is the default, with the approved hero image, neutral shading and no red angled cut into the next section. The supplied cleaner crest is in the top-left. The subtle Powered by Bannerforge Studios credit remains.
- **History:** six selectable eras with stories, dated evidence and films inside each era. Existing catalogue totals and source material are retained, not rewritten as invented history.
- **Roster:** searchable, filterable evidence table, 25 names per page, expandable sources, no Steam profile links. Record years are explicitly not join/discharge dates.
- **Events:** agenda and month modes, interactive briefing, full visible-range loading, labelled blue Public Server, green Linebattle and crimson Competitive categories. Chicago date handling is independent of the viewer's device timezone.
- **Staff workspace:** grouped task navigation, one stat-review workspace, proof inspection and round editing, explicit member selection for rank/medal actions, separate artwork catalogues, attendance workspace and review-queue filters. Existing RPC and mutation contracts were retained.

The research shaped the separation between a visual member record and a functional staff workspace. See [Community design research](COMMUNITY-DESIGN-RESEARCH.md), which distinguishes public primary-source observations from recommendations and inaccessible live pages.

## Database release gate: medal visibility

`site/db/0048_medal_profile_visibility.sql` is a **draft, not applied**. It adds the display preference and an owner/staff RPC, with a visibility-only branch in the existing audit trigger. It retains the existing 75-entry audit-retention mechanism and requires the assignment/audit-retention triggers to exist before committing.

Real profile controls require that migration. Missing or failed preference reads retain ranks and owner/staff award records, disable saving and withhold the medal display rather than assume hidden awards are public. Do not publish this frontend before the matching schema and role tests are ready.

Before any live application, verify the actual target definitions and backup, execute the migration in a disposable database, then test the matrix in [Medal display preferences](medal-visibility.md). Required paths include owner, staff, ordinary member targeting another member, guest and disabled member; one audit for a real change, none for a repeated value; failure rollback and the latest-75 cap. Static checks are not proof of those behaviours. No live awards need deletion for these tests.

## Other unresolved integration findings

1. Public monthly `0039` and weekly `0046` leaderboards still use submission creation time. Personal Day/Week/Month now uses linked event occurrence in Chicago. Reconcile these separate aggregate contracts in a reviewed backend pass before claiming all period statistics agree.
2. All-time voice hours use the existing sample-backed member RPC. Period-specific hours, qualified-event count and attendance percentage need a member-safe aggregate with verified cadence, AFK exclusions and grace-window rules. Unavailable values are N/R, never inferred from RSVP intent.
3. Member media-submission and weekly-feature counts remain visibly unconnected rather than fabricated.
4. Existing weekly publication-on-load remains in the parent Home/admin workflow. Moving publication to a controlled server process needs a separate reviewed change.
5. Some pre-existing staff mutations and audit writes are separate operations. Making every edit and audit atomic is backend work, not established by this visual pass.
6. Live RSVP sync, Discord edits, proof-storage authorization, uploads/transcoding, real owner/staff preference persistence and live authentication still require controlled end-to-end checks.
7. The read-only status check during this turn reported stale/failed house-rules, server-status and Steam-presence background jobs. Those operational findings were not changed or hidden by the redesign. Private backup status was not verified.

No commit, push, Cloudflare publish, migration, bot restart or live-account mutation was performed. Existing uncommitted work was preserved. The built site remains in `site/dist`; production files at the repository root were not replaced.
